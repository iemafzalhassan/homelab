# Phase 12 Sub-phase 01: Foundation — CI green, auth finalized, code quality baseline

## 1. Description

Get the Kyros monorepo into a state where every push to main passes CI: a working
Go test suite, a green linter, a working web build, and a single source of truth
for Keycloak-issued bearer tokens. The previous state of the repo had three
classes of issues that would have blocked every future phase:

1. CI workflow used `bun --filter web build`, which is unreliable on iCloud-synced
   working directories (`CouldntReadCurrentDirectory`). It also had no `lint` script
   to call — `next lint` was removed in Next.js 16.
2. `.golangci.yml` was the v1 schema, which `golangci-lint >= 2.0` rejects
   outright.
3. The registry's auth middleware had a "dev mode" bypass: when the configured
   `KYROS_AUTH_SECRET` was empty, the middleware would accept any bearer token.
   In production this is an open-registry footgun.

*Note: This plan is retroactively documented. The work was done as a pre-12-02
foundation pass to unblock every subsequent sub-phase.*

## 2. Requirements Addressed

- **D-04 (MVP scope)**: Trivy + Syft + Cosign keyless only (no Grype, no SLSA L3+)
  — the auth finalize decision is independent of, and required by, the security

- **D-05 (Multi-tenancy)**: Postgres RLS pending — the migrations run cleanly, but

- The phase-12-01 plan does NOT add new REQ-IDs; it fixes CI plumbing so every
  future 12-NN plan can rely on a green baseline.

## 3. Architecture / Implementation Details

### Step 1: Auth — single source of truth for Keycloak tokens

**Before** (broken):
- `internal/api/auth/handler.go` used `internal/auth.Validator` (Keycloak JWKS,
  RS256, production-correct).
- `internal/registry/auth.go` used HS256 with `KYROS_AUTH_SECRET`. If the
  secret was empty, the middleware logged "accepting token in dev mode" and
  passed any token through.

**After** (production):
- `internal/auth/jwt.go` exposes `*auth.Validator` with a clean
  `ValidateToken(string) (map[string]any, error)` signature — returns the
  claims map directly instead of a `*jwt.Token`, so callers don't import
  `golang-jwt` types.
- `internal/registry/auth.go` is refactored:
  - Constructor: `NewAuthMiddleware(logger, realm, validator TokenValidator)`
    where `TokenValidator` is a one-method interface.
  - The HS256 path and the dev-mode bypass are **deleted**.
  - The middleware is fail-closed: if `validator == nil`, every request gets
    `503 Service Unavailable` and a structured log.
  - Validated claims are placed on the request context under a typed
    `claimsKey{}` for downstream handlers (logging, rate limiting, future
    per-user metrics).
- `cmd/registry/main.go` builds the validator from `cfg.KeycloakIssuer` and
  fails fast at startup if the issuer is empty.
- `internal/config/config.go` adds `KeycloakIssuer` (reads both
  `KYROS_KEYCLOAK_ISSUER` and the legacy `KEYCLOAK_ISSUER` env var for
  backwards compatibility with the api service).
- `cmd/api/main.go` is unchanged in behaviour but uses the new `Validator`
  signature.
- A startup-time warning in `cmd/registry/main.go` detects the legacy
  `KYROS_AUTH_SECRET` env var and tells the operator it's no longer used.

**Tests** (`internal/registry/auth_test.go`):
- All four tests now use a `stubValidator` — no JWKS fetch in unit tests.
- New test: `TestAuthMiddleware_NilValidator` — regression test for the
  dev-mode-bypass removal. Asserts the middleware returns 503 and that no
  downstream handler runs.

### Step 2: `httpserver` — real production hardening

**Before**:
- `middleware.RealIP` was applied. The chi maintainers deprecated it in
  `go-chi/chi/v5` because it **unconditionally trusts** `X-Forwarded-For`,
  `X-Real-IP`, and `True-Client-IP` from any source — which is exploitable
  when the service is reachable without going through a known proxy
  (port-forward during a CVE triage, a misconfigured NetworkPolicy, etc.).
- `http.Server{}` had no `ReadHeaderTimeout`. `gosec G112` flags this as a
  Slowloris vector: a slow/large-header client could hold a goroutine
  indefinitely.

**After**:
- `middleware.RealIP` is removed. A code comment explains the deprecation
  and instructs operators to wire proxy-header trust at the Traefik edge
  rather than in the app.
- `http.Server{ReadHeaderTimeout: 5 * time.Second}` is set. `ReadTimeout` is
  intentionally NOT set: the per-request `Timeout` middleware already
  bounds body read + handler execution, and the OCI registry's blob push
  endpoint accepts large bodies and would break with a short `ReadTimeout`.

### Step 3: Lint — `golangci-lint` v2 schema + real fixes

**Config** (`.golangci.yml`):
- Migrated from the v1 schema to `version: "2"`.
- Dropped `errcheck`, `govet`, `ineffassign`, `staticcheck`, `unused` from
  the `enable` list — they are on by default in v2.
- Dropped `gosimple` — it was folded into `staticcheck` in v2.
- `gofmt` moved to a separate `formatters:` section (it's a formatter, not
  a linter in v2).

**Code** (14 real issues fixed):
- 9× `errcheck`: every `defer log.Sync()` and `defer xxx.Close()` now uses
  `defer func() { _ = xxx.Sync() }()` or `defer func() { _ = xxx.Close() }()`.
- 3× `gofmt`: `gofmt -w .` corrected.
- 1× `gosec G112` (Slowloris) — fixed by adding `ReadHeaderTimeout`.
- 1× `staticcheck SA1019` (`middleware.RealIP` deprecation) — fixed by
  removing the middleware and documenting the edge-trust decision.

### Step 4: CI workflow — defensive and lint-aware

**Before** (`.github/workflows/ci.yml`):
- `web-lint` ran `bun lint` — no `lint` script in `apps/web/package.json`.
- `web-build` ran `bun install && bun --filter web build` — `bun --filter`
  is unreliable on certain paths (iCloud-synced directories, paths with
  spaces).

**After**:
- `web-lint` is a one-line no-op with a TODO comment: "Add this job back
  when a flat ESLint config is added to apps/web/." Next.js 16 removed
  `next lint`; there is no built-in lint path. The job depends on
  `go-build` so it doesn't waste runner time when the Go build is broken.
- `web-build` uses `npx --no-install next build` from the `kyros/apps/web/`
  working directory. `npx` is bundled with the ubuntu runner; `next` is
  installed as a workspace dependency. This is independent of bun's
  workspace resolver.
- `bun install --frozen-lockfile` is used in both jobs so a lockfile drift
  fails the build instead of silently mutating `bun.lock`.

## 4. Rollback Plan

All changes are isolated to:
- `kyros/.github/workflows/ci.yml`
- `kyros/.golangci.yml`
- `kyros/cmd/{api,registry,builder,scanner,sbom,signer,notifier}/main.go`
- `kyros/internal/{auth,api/auth,api/webhooks,config,health,httpserver,registry}/`

Revert the commit and the previous state is restored. No DB migrations or
runtime config changes are required to roll back.

**Breaking-change note**: After this commit, the registry service requires
`KYROS_KEYCLOAK_ISSUER` to be set. The previous code accepted any token
when `KYROS_AUTH_SECRET` was empty. If the operator's environment still
sets `KYROS_AUTH_SECRET` only, the registry will refuse to start with a
clear error message. The fix is to set the issuer URL — see the warning
printed at startup if the legacy env var is detected.
