# Phase 6: GitOps Bootstrap

## 1. Description
This plan covers the bootstrapping of ArgoCD on the AKS cluster and the establishment of the App-of-Apps GitOps pattern. 

*Note: This plan is retroactively documented, as the phase was already successfully implemented to unblock core platform functionality.*

## 2. Requirements Addressed
- **GITOPS-01**: ArgoCD deployed via Helm bootstrap; subsequent ArgoCD upgrades managed by ArgoCD itself (self-managed)
- **GITOPS-02**: App-of-Apps pattern: single root `Application` in ArgoCD manages all platform Applications
- **GITOPS-03**: ArgoCD server accessible via `HTTPRoute` at `argocd.yourdomain.com` with TLS
- **GITOPS-04**: ArgoCD sync automatically reconciles any manual `kubectl` changes (auto-heal enabled on platform apps)
- **GITOPS-05**: ArgoCD ApplicationSet used for workload apps (directory-based generator on GitOps repo)

## 3. Architecture / Implementation Details

### Step 1: ArgoCD Helm Bootstrap
- Define `manifests/bootstrap/argocd/values.yaml`.
  - Disable bundled ingress/HTTPRoute.
  - Disable bundled dex/redis HA to save memory.
- Create `install.sh` to apply the Helm chart using `helm template` and `kubectl apply` directly.

### Step 2: Ingress and TLS (Gateway API)
- Define `argocd-httproute.yaml` in the bootstrap directory.
- Attach the `HTTPRoute` to the Traefik `Gateway` in the `traefik` namespace.
- Enable cross-namespace reference using `ReferenceGrant`.

### Step 3: Git Authentication
- Create `repo-secret.yaml` to configure the SSH/PAT credentials for accessing the private repository.

### Step 4: App-of-Apps Pattern
- Create `manifests/apps/root.yaml` which defines the root ArgoCD Application.
- The root App points to the `manifests/apps/` directory in the Git repo.
- Populate `manifests/apps/` with:
  - `argocd.yaml` (Self-management)
  - `traefik.yaml`
  - `cert-manager.yaml`
  - `cert-manager-extras.yaml`
  - `argocd-extras.yaml`

## 4. Rollback Plan
- Run `helm uninstall argocd -n argocd` and delete the `argocd` namespace.
