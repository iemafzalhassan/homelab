# Plan 11-03: Jenkins CI Pipeline & E2E Verification

## Objective
Set up the Jenkins CI pipeline (`Jenkinsfile.demo`) for the minimal demo app (`homelab-demo`) to build and push container images to ACR and commit tag updates. Add Keycloak client and RBAC documentation to `docs/ADR-001-platform-auth-rbac.md`, configure Jenkins Job DSL for the pipeline, and perform end-to-end verification.

## Must Haves
- The demo app must have a static `Dockerfile` and `index.html` in `apps/homelab-demo/`.
- `index.html` must contain a version placeholder `VERSION_PLACEHOLDER`.
- The pipeline `Jenkinsfile.demo` must use the `kaniko` agent pod, schedule on spot nodes, replace the placeholder in `index.html` with the Git SHA, push to ACR, and push the tag update back to `manifests/apps/homelab-demo/uat/deployment.yaml` in the `main` branch.
- Jenkins JCasC jobs block in `manifests/bootstrap/jenkins/values.yaml` must be updated to register `homelab-demo` pipeline using Job DSL.
- Update `docs/ADR-001-platform-auth-rbac.md` with Kargo OIDC client configuration details and groups-to-roles RBAC mappings.
- Fully verify end-to-end promotion flow.

### Prohibitions
- Do not use static/hardcoded credentials for Jenkins JNLP agents or Kaniko builders (must use Workload Identity).
- Do not push JNLP agent containers to the system node pool.
- Do not authorize the Keycloak developers group to approve PROD promotions.

## Verification
1. Verify Jenkins job registration:
   - Access `https://jenkins.smapatticare.com`.
   - Log in using Keycloak credentials.
   - Verify `homelab-demo` pipeline job is created.
2. Trigger the CI build:
   - Run the `homelab-demo` pipeline build.
   - Check build logs to ensure Kaniko successfully pushes the image to ACR.
   - Verify the git commit is pushed to the repo.
3. Verify Freight creation:
   - Access Kargo CLI or UI.
   - Run `kubectl get freight -n homelab-demo` to ensure Kargo has detected the commit and created a new Freight.
4. Verify Auto-Promotion to UAT:
   - Check that `homelab-demo-uat` ArgoCD Application updates the target commit and syncs.
   - Run `kubectl describe pod -n demo-uat -l app=homelab-demo` and verify the image tag matches the built Git SHA.
5. Verify PROD Promotion Gate:
   - Log in to Kargo UI at `https://kargo.smapatticare.com` as a user in the `developers` group (e.g. `dev@smapatticare.com`).
   - Attempt to promote the UAT Freight to PROD. Verify access is denied/restricted.
   - Log in as a user in the `devops` group (e.g. `devops@smapatticare.com`).
   - Click "Promote" on the UAT Freight, select the PROD stage, and confirm.
   - Verify that Kargo triggers the promotion step, updating `homelab-demo-prod` application, and the pod in `demo-prod` namespace restarts with the new version.

## Threat Model
<threat_model>
- **Threat:** Git credential leakage from Jenkins JNLP build agents.
  - **ASVS Control:** V2.10.3 (Secret Storage / Kubernetes mounts).
  - **Mitigation:** Use Jenkins credentials provider and Workload Identity annotation to authenticate JNLP agents to ACR/Git without persistent static secrets.
- **Threat:** Container image spoofing or poisoning in ACR.
  - **ASVS Control:** V1.11.1 (Verification / Supply chain security).
  - **Mitigation:** Enforce Workload Identity federation on JNLP build pods so that only authorized, ephemeral containers spawned by Jenkins can push to the ACR repository.
- **Threat:** Unauthorized access to Keycloak client configuration or redirect URIs.
  - **ASVS Control:** V1.2.2 (OIDC configuration security).
  - **Mitigation:** Document client specification in ADR-001. Ensure OIDC client is restricted to secure callback URLs (`https://kargo.smapatticare.com/auth/callback`) to prevent token leakage.
</threat_model>
