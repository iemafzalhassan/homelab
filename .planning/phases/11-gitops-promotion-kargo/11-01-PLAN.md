# Plan 11-01: Kargo Install via ArgoCD

## Objective
Deploy Kargo v1.10.8 to the `kargo` namespace on the AKS spot node pool using the ArgoCD App-of-Apps pattern. Expose the Kargo UI at `https://kargo.smapatticare.com` using a Traefik HTTPRoute, and configure Keycloak OIDC SSO with Keycloak groups mapped to Kargo admin/viewer roles.

## Must Haves
- Kargo namespace must be created automatically.
- All Kargo pods must be scheduled on the spot node pool using:
  ```yaml
  nodeSelector:
    kubernetes.azure.com/scalesetpriority: "spot"
  tolerations:
    - key: "kubernetes.azure.com/scalesetpriority"
      operator: "Equal"
      value: "spot"
      effect: "NoSchedule"
  ```
- Resource limits must be set for API (`100m CPU / 128Mi RAM` requests, `500m CPU / 256Mi RAM` limits) and Controller (`200m CPU / 256Mi RAM` requests, `1000m CPU / 512Mi RAM` limits).
- The Traefik HTTPRoute must route `kargo.smapatticare.com` securely via the `websecure` Gateway entrypoint to `kargo-api:8080`.
- A ReferenceGrant must permit Traefik Gateway (namespace `traefik`) to route to Kargo service.
- Keycloak integration must use the `Platform` realm and require PKCE.
- Client secret must be loaded dynamically from Kubernetes Secret `kargo-oidc-secret` (key: `client-secret`) inside the `kargo` namespace.

### Prohibitions
- Do not hardcode or commit OIDC client secrets to Git.
- Do not expose the Kargo UI over unencrypted HTTP (use Gateway `websecure` entrypoint only).
- Do not run Kargo components on the system node pool (must use spot pool).

## Verification
1. Verify Kargo namespace creation:
   ```bash
   kubectl get ns kargo
   ```
2. Verify all Kargo pods schedule on spot pool and are running:
   ```bash
   kubectl get pods -n kargo -o wide
   ```
   Check that IP/Node schedules on the spot node pool.
3. Verify OIDC environment variable injection:
   ```bash
   kubectl describe pod -n kargo -l app.kubernetes.io/name=kargo
   ```
   Check that `OIDC_CLIENT_SECRET` is populated from the `kargo-oidc-secret` Secret.
4. Verify HTTPRoute exists and is attached to Traefik:
   ```bash
   kubectl get httproute kargo -n kargo
   ```
5. Test curl to Kargo endpoint:
   ```bash
   curl -kI https://kargo.smapatticare.com
   ```
   Should return an HTTP redirect status (302) redirecting to the Keycloak OIDC login screen.

## Threat Model
<threat_model>
- **Threat:** Bypassing Kargo Authentication via misconfigured OIDC.
  - **ASVS Control:** V1.2.1 (OIDC authorization flow authentication checks).
  - **Mitigation:** Require PKCE validation at the Keycloak client level. Map groups explicitly and do not allow default login permissions for unspecified groups.
- **Threat:** Unauthorized access to secrets (Client Secret in Repo).
  - **ASVS Control:** V2.10.1 (No secrets in source code).
  - **Mitigation:** Use a Kubernetes Secret `kargo-oidc-secret` injected dynamically through environment variables; never hardcode or commit the secret values to Git.
- **Threat:** Unauthorized promotion or configuration changes through Kargo API.
  - **ASVS Control:** V1.4.1 (Access Control / Ingress protection).
  - **Mitigation:** Traefik HTTPRoute terminates TLS at Gateway and proxies to Kargo namespace only; ReferenceGrant restricts route binding to Traefik Gateway namespace.
</threat_model>
