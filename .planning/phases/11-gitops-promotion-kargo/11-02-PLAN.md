# Plan 11-02: Demo App & Kargo CRs

## Objective
Set up the minimal demo application (`homelab-demo`) with its Kubernetes manifests for UAT (`demo-uat` namespace) and PROD (`demo-prod` namespace) overlays. Establish the Kargo Custom Resources (Project, Warehouse, Stages) to handle automated promotion to UAT and manual approval before promoting to PROD.

## Must Haves
- The demo application must be configured in `manifests/apps/homelab-demo/uat` and `manifests/apps/homelab-demo/prod`.
- The UAT application `homelab-demo-uat` must have auto-sync enabled in ArgoCD.
- The PROD application `homelab-demo-prod` must NOT have `syncPolicy.automated` configured (manual sync only).
- Both ArgoCD Applications must have `kargo.akuity.io/authorized-stage` annotation:
  - UAT: `kargo.akuity.io/authorized-stage: "homelab-demo:uat"`
  - PROD: `kargo.akuity.io/authorized-stage: "homelab-demo:prod"`
- Kargo Project `homelab-demo` must specify `autoPromotionEnabled: true` for `uat` and `autoPromotionEnabled: false` for `prod`.
- Kargo Warehouse must watch `manifests/apps/homelab-demo/` on `main` branch.
- Kargo Stages must use the `argocd-update` step pointing to their respective ArgoCD Applications.
- Create `manifests/apps/kargo-resources.yaml` to deploy Kargo CRs via ArgoCD pointing to the `kargo/` folder.

### Prohibitions
- Do not enable `syncPolicy.automated` for the PROD demo application (`homelab-demo-prod`).
- Do not deploy Kargo CRs to namespaces other than `homelab-demo` or target namespaces other than `demo-uat` / `demo-prod`.
- Do not allow Kargo to modify ArgoCD Applications without the `kargo.akuity.io/authorized-stage` annotation.

## Threat Model
<threat_model>
- **Threat:** Race conditions leading to configuration drift in PROD.
  - **ASVS Control:** V1.11.10 (Process controls for deployments / CI-CD configuration).
  - **Mitigation:** Enforce manual sync in ArgoCD for the PROD app (`syncPolicy: {}`). Kargo exclusively initiates and coordinates PROD syncs.
- **Threat:** Unauthorized Kargo stage manipulation by ArgoCD.
  - **ASVS Control:** V1.4.1 (Access Control / Ingress protection / Identity separation).
  - **Mitigation:** Restrict Kargo access to ArgoCD Applications using the annotation `kargo.akuity.io/authorized-stage`. The Kargo controller will reject modifying any Application without this mapping.
- **Threat:** Promotion of untested code to PROD.
  - **ASVS Control:** V1.11.1 (Verification gates / separation of concerns).
  - **Mitigation:** PROD stage `requestedFreight` explicitly specifies UAT as the only source stage (`stages: ["uat"]`), ensuring code must run in UAT before promotion.
</threat_model>
