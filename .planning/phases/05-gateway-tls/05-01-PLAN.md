# Phase 5: Gateway & TLS Implementation Plan

This phase will configure external HTTPS routing into the AKS cluster using **Traefik v3** powered by the **Kubernetes Gateway API** and automatic wildcard TLS certificates managed by **cert-manager** (via Cloudflare DNS-01 challenges).

We will use bash bootstrap scripts and Helm commands for the initial installation. In Phase 6, we will easily migrate these to ArgoCD.

## User Review Required

> [!IMPORTANT]
> The Cloudflare API token is in Key Vault, but the Secrets Store CSI driver requires a Pod to actively mount the secret for it to be synced as a Kubernetes `Secret`. Since `cert-manager` itself does not inherently mount this CSI volume, we will deploy a lightweight "sync" Deployment (a `busybox` container running `sleep infinity`) in the `cert-manager` namespace. This pod's sole purpose is to mount the `SecretProviderClass` and keep the Cloudflare API token synced as a Kubernetes Secret for cert-manager to use.

## Proposed Changes

---

### Gateway API CRDs

We will install the standard channel of the Gateway API CRDs as required by Traefik v3 and cert-manager.

#### [NEW] `manifests/bootstrap/gateway-api/install.sh`
- A script to run `kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.5.1/standard-install.yaml`.

---

### Cert-Manager & Cloudflare Issuer

We will install cert-manager and configure it to issue certificates using Cloudflare DNS-01 challenges. 

#### [NEW] `manifests/bootstrap/cert-manager/values.yaml`
- Helm values to enable the Gateway API feature gate (`config.enableGatewayAPI=true`).

#### [NEW] `manifests/bootstrap/cert-manager/install.sh`
- A script to create the `cert-manager` namespace, add the Jetstack Helm repo, and run `helm upgrade --install cert-manager jetstack/cert-manager`.

#### [NEW] `manifests/bootstrap/cert-manager/csi-secret-provider.yaml`
- A `SecretProviderClass` referencing the `cloudflare-api-token` in Azure Key Vault.
- Configured to output a Kubernetes Secret named `cloudflare-api-token-secret`.

#### [NEW] `manifests/bootstrap/cert-manager/csi-sync-deployment.yaml`
- A lightweight `busybox` deployment that mounts the `SecretProviderClass`.
- Uses the `cert-manager` Workload Identity (which we need to make sure is available).

> [!WARNING]  
> **Identity Missing for Cert-Manager Sync:** In Phase 3, we didn't create a `cert-manager` managed identity to access the Key Vault, but we did create one for `traefik`. Instead of going back to Terraform to create a new identity just for cert-manager right now, we can reuse the `traefik-identity` or `argocd-identity` temporarily for the sync pod, OR we can quickly add a `cert-manager` identity to the Terraform `identity` module. **My strong recommendation is to add `cert-manager` to the Terraform identity module first.** I will include this step in the plan.

#### [MODIFY] `modules/identity/main.tf`
- Add `cert-manager` to the `local.identities` map so it gets a federated identity credential and Key Vault access.

#### [NEW] `manifests/bootstrap/cert-manager/cluster-issuer.yaml`
- A `ClusterIssuer` configured for Let's Encrypt Production, using the Cloudflare API token secret for DNS-01 challenges.

---

### Traefik v3

We will deploy Traefik v3 as the Gateway Controller.

#### [NEW] `manifests/bootstrap/traefik/values.yaml`
- Disable `kubernetesIngress.enabled=false`.
- Enable `kubernetesGateway.enabled=true`.
- Enable `gateway.enabled=true` (this auto-creates the `GatewayClass` and `Gateway`).
- Configure the Workload Identity annotations for the Traefik ServiceAccount.

#### [NEW] `manifests/bootstrap/traefik/install.sh`
- A script to create the `traefik` namespace, add the Traefik Helm repo, and run `helm upgrade --install traefik traefik/traefik`.

#### [NEW] `manifests/bootstrap/traefik/gateway-annotations.yaml`
- A patch/script to annotate the auto-generated `Gateway` resource with `cert-manager.io/cluster-issuer: letsencrypt-prod` so that cert-manager automatically provisions certificates for all attached `HTTPRoutes`.

- Verify the `ClusterIssuer` is marked as `Ready`.
