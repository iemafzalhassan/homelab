## Context

This is Phase 1 of the Kyros platform. Everything starts here. We are building a mixed Go + TypeScript monorepo:

- **Go backend** (single root `go.mod`, `cmd/` pattern, `internal/` for shared packages)
- **Next.js frontend** (Turborepo + pnpm workspaces for TS packages)
- **CI/CD** (GitHub Actions with path-based filtering per service)
- **No codebase yet** — greenfield start

**Key architectural decision from CONTEXT.md:** Single root `go.mod` with `cmd/` per service entry points. This is simpler than multi-module Go workspaces for MVP and avoids `go.work` complexity. Turborepo manages only the TypeScript/Next.js layer.

**Reusable homelab patterns:**
- Traefik HTTPRoute format from `manifests/bootstrap/` (reference for Phase 8)
- Keycloak OIDC pattern from existing homelab services (reference for Phase 3)
- ArgoCD Application format from `manifests/apps/` (reference for Phase 8)

## Plan 1-02: Go Service Skeletons — API + Workers with Health Endpoints

**Objective:** Every Go service has a working HTTP server with `/health`, `/live`, `/ready` endpoints, structured logging, and Prometheus metrics scaffolded.

**Research findings:**
- Pattern: Each service has a `cmd/{service}/main.go` entry point
- Framework: Use `github.com/go-chi/chi/v5` router (lightweight, stdlib-compatible, used by many CNCF projects)
- Logging: `log/slog` (Go 1.21+ stdlib) — structured JSON logging, no external dependency
- Metrics: `github.com/prometheus/client_golang` — standard Prometheus client
- Config: `github.com/spf13/viper` or simple `os.Getenv` — use env vars + viper for flexibility
- Error handling: `github.com/pkg/errors` for stack traces in development

**Go service list** (all follow same pattern):
1. `cmd/api/` — main REST API server
2. `cmd/registry/` — cncf/distribution auth proxy + webhook handler
3. `cmd/scanner/` — NATS consumer: Trivy + Grype runner
4. `cmd/sbom/` — NATS consumer: Syft runner
5. `cmd/signer/` — NATS consumer: Cosign verifier/attacher
6. `cmd/builder/` — NATS consumer: Kaniko job spawner
7. `cmd/notifier/` — NATS consumer: email/webhook sender

**Shared internal packages to scaffold:**
- `internal/httpserver/` — shared HTTP server setup (chi router, middleware, graceful shutdown)
- `internal/health/` — shared `/health`, `/live`, `/ready` handlers
- `internal/metrics/` — shared Prometheus registry + standard metrics
- `internal/logger/` — shared slog JSON logger setup
- `internal/config/` — shared config loading (env vars + viper)

**Tasks:**

1. **Add Go dependencies**:
   ```bash
   go get github.com/go-chi/chi/v5
   go get github.com/prometheus/client_golang/prometheus
   go get github.com/prometheus/client_golang/prometheus/promhttp
   go get go.uber.org/zap            # Rich structured logging (preferred over slog for production)
   go get github.com/spf13/viper
   go get github.com/spf13/cobra     # CLI framework for service commands
   ```

2. **Create `internal/httpserver/server.go`** — shared server struct:
   - chi router setup
   - Standard middleware: RequestID, RealIP, Logger, Recoverer, Timeout
   - `/health` → `{"status":"ok","service":"<name>","version":"<version>"}`
   - `/live` → 200 OK (always, just checks process is alive)
   - `/ready` → checks dependency list (DB, Redis, NATS) and returns 200/503
   - `/metrics` → Prometheus handler
   - Graceful shutdown on SIGTERM/SIGINT (30s timeout)

3. **Create `internal/health/checker.go`** — readiness probe:
   ```go
   type Checker interface {
       Check(ctx context.Context) error
   }
   type ReadinessCheckers map[string]Checker
   // Implementations: PostgresChecker, RedisChecker, NATSChecker
   ```

4. **Create `internal/metrics/registry.go`** — Prometheus metrics:
   - Standard process metrics (auto via `promhttp`)
   - HTTP request duration histogram (labels: method, path, status)
   - Service-specific metrics registered per service

5. **Create each `cmd/{service}/main.go`** skeleton:
   ```go
   package main

   func main() {
       cfg := config.Load()
       log := logger.New(cfg.LogLevel)
       srv := httpserver.New(cfg.Port, log)
       // Register service-specific routes here
       srv.ListenAndServe()
   }
   ```

6. **Verify each service builds and health endpoints work**:
   ```bash
   go build ./cmd/api/ && ./api &
   curl localhost:8080/health  # → {"status":"ok"}
   curl localhost:8080/live    # → 200
   curl localhost:8080/ready   # → 503 (DB not connected, expected)
   curl localhost:8080/metrics # → Prometheus metrics
   ```

**Port assignments:**
| Service | Port |
|---|---|
| api | 8080 |
| registry | 5000 |
| scanner | 8081 |
| sbom | 8082 |
| signer | 8083 |
| builder | 8084 |
| notifier | 8085 |

**Success criteria:**
- [ ] `go build ./...` exits 0 (all 7 services build)
- [ ] `go test ./...` exits 0 (skeleton tests pass)
- [ ] Each service's `/health` returns `{"status":"ok"}` with correct service name
- [ ] Each service's `/metrics` returns valid Prometheus text format
- [ ] Each service shuts down gracefully within 5s of SIGTERM

## Plan 1-04: CI Pipeline — GitHub Actions

**Objective:** GitHub Actions CI validates all Go and TypeScript code on every push with path-based filtering, linting, testing, and Docker image builds.

**Research findings:**
- Path-based triggers: only rebuild services affected by changed files
- Go lint: `golangci-lint` (most comprehensive, includes staticcheck, errcheck, gosec)
- Docker builds: use `docker/build-push-action` — builds OCI image, validates it can run
- OCI conformance: `ghcr.io/opencontainers/distribution-spec` conformance test suite

**Tasks:**

1. **Create `.github/workflows/ci.yml`**:
   ```yaml
   name: CI
   on:
     push:
       branches: [main]
     pull_request:
       branches: [main]
   
   jobs:
     go-lint:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-go@v5
           with: { go-version: '1.23' }
         - uses: golangci/golangci-lint-action@v6
           with:
             working-directory: kyros/
     
     go-test:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-go@v5
           with: { go-version: '1.23' }
         - run: go test ./...
           working-directory: kyros/
     
     go-build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-go@v5
           with: { go-version: '1.23' }
         - run: go build ./...
           working-directory: kyros/
     
     web-lint:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: pnpm/action-setup@v4
         - uses: actions/setup-node@v4
           with: { node-version: '20' }
         - run: pnpm install
           working-directory: kyros/
         - run: pnpm lint
           working-directory: kyros/
     
     web-build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: pnpm/action-setup@v4
         - uses: actions/setup-node@v4
           with: { node-version: '20' }
         - run: pnpm install && pnpm build
           working-directory: kyros/
     
     docker-build:
       runs-on: ubuntu-latest
       strategy:
         matrix:
           service: [api, scanner, sbom, signer, builder, notifier]
       steps:
         - uses: actions/checkout@v4
         - uses: docker/setup-buildx-action@v3
         - name: Build ${{ matrix.service }}
           uses: docker/build-push-action@v6
           with:
             context: kyros/
             file: kyros/cmd/${{ matrix.service }}/Dockerfile
             push: false
             tags: kyros/${{ matrix.service }}:ci
   ```

2. **Create `golangci-lint` config** at `kyros/.golangci.yml`:
   ```yaml
   linters:
     enable:
       - errcheck
       - gosimple
       - govet
       - ineffassign
       - staticcheck
       - unused
       - gosec
       - misspell
       - gofmt
   linters-settings:
     gosec:
       excludes: [G204]  # Subprocess launched from user input (intentional for builder)
   ```

3. **Create Dockerfiles** for each Go service:
   Multi-stage build pattern:
   ```dockerfile
   # Stage 1: Build
   FROM golang:1.23-alpine AS builder
   WORKDIR /build
   COPY go.mod go.sum ./
   RUN go mod download
   COPY . .
   RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /app ./cmd/{service}/

   # Stage 2: Runtime (distroless for security)
   FROM gcr.io/distroless/static-debian12
   COPY --from=builder /app /app
   EXPOSE 808X
   ENTRYPOINT ["/app"]
   ```
   Note: Using `distroless` base image is dogfooding Kyros' own principles!

4. **Create `.dockerignore`** at `kyros/.dockerignore`:
   ```
   .git/
   .planning/
   apps/web/.next/
   node_modules/
   **/*.test.go
   ```

**Success criteria:**
- [ ] All CI jobs pass on `main` branch push
- [ ] `docker build` succeeds for each service producing a valid OCI image
- [ ] `golangci-lint` exits 0
- [ ] `pnpm build` exits 0 for Next.js app

## Plan 1-05: PostgreSQL Schema v1 — golang-migrate Setup + Initial Tables

**Objective:** PostgreSQL schema is initialized with all tables needed for MVP, with golang-migrate managing migrations and tested locally via Docker.

**Research findings:**
- Tool: `golang-migrate/migrate` (most adopted Go migration tool, CLI + library)
- Migration format: Numbered files `NNNNNN_description.up.sql` + `NNNNNN_description.down.sql`
- UUID primary keys: Use `gen_random_uuid()` (PostgreSQL 13+ native, no extension needed)
- Timestamps: Always `TIMESTAMPTZ` (timezone-aware), never `TIMESTAMP`
- Soft deletes: `deleted_at TIMESTAMPTZ` for audit compliance

**Tables (Phase 1 scope — all tables needed through Phase 4):**

```sql
-- Core user/org tables
users (id, keycloak_sub, email, display_name, avatar_url, created_at, updated_at)
organizations (id, slug, display_name, description, avatar_url, created_at)
org_members (org_id, user_id, role, joined_at)
teams (id, org_id, slug, display_name)
team_members (team_id, user_id)

-- Registry tables
repositories (id, org_id, slug, description, visibility, created_at)
tags (id, repo_id, name, digest, manifest_digest, pushed_at, pushed_by)
manifests (id, repo_id, digest, media_type, size_bytes, config_digest, layers_json, created_at)
blobs (digest, repo_id, size_bytes, created_at)

-- Security pipeline tables
scans (id, manifest_digest, scanner, status, started_at, completed_at, result_json)
sboms (id, manifest_digest, format, version, content_json, created_at)
vulnerabilities (id, scan_id, cve_id, severity, package_name, package_version, cvss_score, description)
trust_scores (manifest_digest, score, cve_score, sbom_score, slsa_score, signing_score, freshness_score, provenance_score, calculated_at)

-- API tokens
api_tokens (id, user_id, name, token_hash, scopes_json, expires_at, last_used_at, created_at)

-- Audit log
audit_logs (id, actor_id, action, resource_type, resource_id, metadata_json, created_at)
```

**Tasks:**

1. **Add golang-migrate dependency**:
   ```bash
   go get github.com/golang-migrate/migrate/v4
   go get github.com/golang-migrate/migrate/v4/database/postgres
   go get github.com/golang-migrate/migrate/v4/source/file
   ```

2. **Create migration files** at `database/migrations/`:
   - `000001_create_users_orgs.up.sql` — users, organizations, org_members, teams, team_members
   - `000001_create_users_orgs.down.sql` — DROP TABLE in reverse order
   - `000002_create_registry.up.sql` — repositories, tags, manifests, blobs
   - `000002_create_registry.down.sql`
   - `000003_create_security.up.sql` — scans, sboms, vulnerabilities, trust_scores
   - `000003_create_security.down.sql`
   - `000004_create_tokens_audit.up.sql` — api_tokens, audit_logs
   - `000004_create_tokens_audit.down.sql`

3. **Create `database/schema.sql`** — combined snapshot (for documentation + cold start)

4. **Add migration runner to API** (`internal/db/migrate.go`):
   - Auto-run pending migrations on startup (configurable via `RUN_MIGRATIONS=true`)
   - Log each migration applied

5. **Create `docker-compose.dev.yml`** at `kyros/` for local development:
   ```yaml
   services:
     postgres:
       image: postgres:17-alpine
       environment:
         POSTGRES_DB: kyros
         POSTGRES_USER: kyros
         POSTGRES_PASSWORD: kyros_dev
       ports: ["5432:5432"]
       volumes: ["postgres_data:/var/lib/postgresql/data"]
     redis:
       image: redis:7-alpine
       ports: ["6379:6379"]
     nats:
       image: nats:2-alpine
       command: ["-js"]
       ports: ["4222:4222", "8222:8222"]
   volumes:
     postgres_data:
   ```

6. **Verify migrations**:
   ```bash
   docker-compose -f docker-compose.dev.yml up -d postgres
   # Wait 5s
   migrate -path ./database/migrations -database "postgres://kyros:kyros_dev@localhost:5432/kyros?sslmode=disable" up
   # Check: all 4 migrations applied
   # Check: tables exist via psql
   ```

**Success criteria:**
- [ ] `migrate up` applies all 4 migrations without errors
- [ ] `migrate down` reverts all migrations without errors
- [ ] All tables exist with correct columns and types
- [ ] API service connects to local PostgreSQL on startup (`/ready` returns 200 with DB connected)
- [ ] `migrate up` is idempotent (running twice does not error)

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| ShadCN monorepo init changes behavior between versions | Medium | Low | Pin shadcn CLI version; test init in isolation first |
| Go distroless base missing required system libs | Low | Medium | Test docker run after build; switch to `gcr.io/distroless/base-debian12` if needed |
| PostgreSQL schema gaps discovered in Phase 2 | Medium | Low | Migrations are additive; add new columns in Phase 2 migration |
| pnpm/Turborepo workspace resolution issues | Low | Medium | Fall back to workspace: `*` version specifier if specific version causes issues |
| GitHub Actions minutes budget on free tier | Low | Low | Use path filters to skip unchanged services; cache Go modules + pnpm store |
